# 开发日志

这份日志记录项目阶段性设计决策、已完成能力和遗留问题。它不同于 `CHANGELOG.md`：`CHANGELOG.md` 面向用户和发布版本，这里面向后续开发、换电脑接手和代码维护。

## 当前定位

InSAR Studio 不替代 SARscape、ISCE、MintPy、SNAP 或 ASF Vertex。项目定位是处理前的数据准备助手，重点把 AOI、SAR 影像、精密轨道、DEM、缓存、任务队列和目录组织做清楚。

## 设计原则

- 用户可以不从头走完整流程：Sentinel-1 下载、DEM 下载、本地 DEM 转换、精密轨道等功能应尽量可单独使用。
- 账号、Token、缓存、下载历史、任务状态必须有明确反馈，不能只显示一个笼统的成功或失败。
- 地图和列表应联动：点击 SAR 列表或地图边框时要高亮目标，并显示可读元数据。
- 任务不能因为切换界面或重启软件而丢失状态；暂停、结束、失败、删除应分别处理。
- 主程序保持轻量，大体积 DEM/GDAL 高程基准能力通过组件化按需安装。
- 公开仓库、发行包、Release 说明不得包含个人路径、密钥、测试缓存、下载成果或私有数据。

## v2.1 系列已完成

### UI 与布局

- 采用左侧功能区、右侧地图的工作台布局。
- 顶部资源功能区支持 Sentinel-1、DEM、精密轨道、GACOS、Sentinel-2、Landsat、HLS 等入口。
- 设置、资源下载、下载中心固定在左侧主功能区。
- 新手教程只在首次打开软件时自动显示一次，之后可通过顶部入口手动重播。

### Sentinel-1 / ASF

- 支持 ASF 检索 SLC/GRD，并在地图显示 SAR 影像边框。
- 支持按 AOI、日期、轨道方向、极化、Path/Frame 等条件筛选。
- SAR 工作台支持搜索、勾选、全选当前结果、清空、单景高亮、单景下载。
- 下载任务支持并发、暂停、继续、结束、失败重试和断点续传。
- 下载中心和工作台使用同一批任务状态，任务记录可持久化。

### AOI 与边界

- 支持绘制 AOI、手动经纬度范围、本地边界文件导入、多要素预览和选择。
- 行政区和上传边界都应能绑定到同一 AOI 状态，供 ASF、DEM、Orbit 等功能复用。
- 正式项目建议用户上传权威边界文件，内置或在线行政区适合快速筛选和预览。

### DEM

- 支持仅下载 DEM，以及下载后转换为椭球高并导出 SARscape 常用文件。
- 支持本地 DEM 转换椭球高、转换 SARscape 格式。
- DEM/GDAL 高程基准组件按需安装，规划中需要完整覆盖 GDAL/rasterio/numpy/PROJ、EGM96、EGM2008 和 WGS84 椭球高输出。
- 当前重点遗留：椭球高转换必须使用正确的垂直基准网格，不能在缺少 EGM2008 时静默采用粗略近似。

### 精密轨道

- 默认承接 Sentinel-1 检索或导入的 SAR 影像列表，匹配下载对应 POEORB/EOF。
- 支持从 SAR 影像目录、ASF 官方脚本或 metadata 文件中解析候选。
- 输出目录应按 `Sentinel_Orbit/AUX_POEORB` 组织。
- 太新的影像如暂未发布精密轨道，应给出可理解原因。

### 设置与凭据

- Earthdata/ASF、OpenTopography 等凭据保存前需要校验。
- Earthdata/ASF 状态区分本机已保存凭据、正在检测、检测通过、检测失败、未配置。
- 输入框不回填密钥，避免明文泄露；需要确认时使用小眼睛查看用户当前输入。
- 失败凭据有短时间冷却，避免连续错误登录导致账号受限。

### 发布与更新

- GitHub Release 可自动生成单文件便携版、安装包、便携 zip、DEM/GDAL 组件包、组件清单和校验文件。
- 软件内可检测 GitHub Release 新版本。
- 目前在线更新仍是下载更新包/启动安装器阶段，真正静默覆盖更新、进程退出、校验、回滚仍在后续开发。
- 已加入发布脚本中文弯引号检查，防止 PowerShell/YAML 解析失败。

## 仍需优先攻克

1. 安装版的一键覆盖更新：下载、校验、关闭当前进程、启动安装器或独立 updater、失败回滚。
2. DEM/GDAL 高程基准组件闭环：组件 manifest、下载进度、校验、安装目录、修复/卸载、转换前强校验。
3. Sentinel-2、Landsat、HLS 接入：先规划数据源、检索字段、下载授权和缓存策略。
4. SAR 工作台二级任务管理：单景立即开始、暂停、继续、失败重试的状态要继续细化。
5. 多要素 AOI 输出策略：合并下载和按要素拆分下载都要有清晰目录规则。
6. 减小主程序体积：继续外置高程转换组件，评估动态加载、代码拆分和依赖精简。

## 维护提醒

- 发布前必须跑基础检查，至少包括前端构建、Python 编译、版本检查、中文弯引号检查。
- 不要把 `dist/`、`release/`、本地边界、测试下载数据、缓存、截图批量文件提交到仓库。
- Release 正文和 README 不要写本机路径。
- `CHANGELOG.md` 写用户可感知变化，本文档写开发背景和后续接手信息。
